# マージ後の後片付け

**次の作業を始める前に、必ずここを通す。**

## 1. マージされたことを確認する

```bash
gh pr list --state merged --limit 5
git log --oneline origin/main -5
```

## 2. 既定ブランチを最新化し、リモート追跡参照を整理する

```bash
git switch main
git pull --prune
```

**ここを飛ばすと次のブランチが古い基点から切られる。** マージ済みの変更が入っていない
状態で作業することになり、PR を出す段でコンフリクトになる。

`--prune` は GitHub 上で消えたリモートブランチに対応する `origin/…` の追跡参照をローカルから落とす。
リモートブランチ自体はマージ時に GitHub が自動削除する設定（`delete_branch_on_merge`）になっている。
消えていない場合は GitHub 側の設定を確認する。

## 3. 不要になったローカルブランチを消す

```bash
git branch --merged main
```

出てきたもののうち **`main` 自身を除いて**削除する。

```bash
git branch -d <ブランチ名>
```

`git branch -d` が「マージされていない」と拒否した場合は**強制削除しない。**
本当にマージされているか確認する。Squash マージだと `--merged` に出ないことがあるが、
このリポジトリはマージコミット固定なので、拒否されたなら何か別の理由がある。

## 4. 用済みのプランを片付ける

```bash
node scripts/plan-store.cjs gc
```

消えたブランチに紐付いていたプランを `plans/` から削除する。
**ブランチに紐付いていないプラン（着手前の計画）は消えない。**

`.githooks/reference-transaction` が効いていればブランチ削除の時点で片付いている。
**そのときこのコマンドは何もしない（冪等）ので、そのまま実行してよい。**
何が残っているか見たいときは `node scripts/plan-store.cjs status`。

## 5. Issue が閉じたか確認する

```bash
gh issue list --state open
```

`Closes #<番号>` が正しく効いていれば、マージと同時に閉じている。
**開いたままなら、PR 本文に `Closes #` が入っていなかった可能性がある。** 手で閉じ、
次回から漏らさないようにする。

## 6. 次の作業へ

次の依頼があれば `start-issue-work` スキルへ進む。

> 完了の目安: `main` が最新で、マージ済みのローカルブランチが残っておらず、
> `git branch -r` に消えたブランチの追跡参照（`origin/feature/…` など）も残っておらず、
> 終わった作業のプランが `plans/` に残っていない。
