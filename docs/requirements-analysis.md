# 交通費精算アプリ 要求分析

## 1. この文書について

この文書は、交通費精算アプリを **なぜ作るのか**・**何が欲しいのか** を、依頼者本人の言葉に沿って
整理したものである。要件定義（`docs/requirements.md`、今後作成）の手前に置く。

- **扱うこと** — 現状の困りごと、実現したいこと、やらないこと、まだ決まっていないこと
- **扱わないこと** — 画面設計、データ構造、技術選定、実装方式。これらは要件定義以降で決める
- **出どころ** — 依頼者本人へのヒアリング（口述および確認質問）
- **更新の仕方** — 「8. 未確定事項」が埋まったらこの文書を直す。要件定義の途中で要求がひっくり返った
  場合も、**なぜひっくり返ったか**を添えてここへ書き戻す

## 2. 背景

- 依頼者は **結婚式のビデオグラファー**。企業からの業務委託を受け、結婚式場で結婚式の動画を撮影している
- 稼働日は主に **土日**
- 撮影業務の依頼は **メール** で届く。独自ドメインを Google Workspace に登録し、**Gmail** で管理している
- 依頼メールをもとに仕事を受注し、受注した案件ごとに交通費が発生する
- **月初に、前月分の交通費を委託元へ提出する。** 提出形式は委託元が用意した Google スプレッドシート
- 精算する交通費は **公共交通（電車・バス）** と **タクシー** の2つ
- 現場までの経路は会場ごとに固定ではない。単純な1区間のこともあれば、途中駅で乗り換えることもあり、
  **同じ会場でも複数の行き方がある**
- タクシーに乗るかどうかも事前には決まらない。
  **その日にどの経路を使ったかが確定するのは、1日の終わり**である

## 3. 現状の業務フロー（As-Is）

1. **依頼を受ける** — 委託元から撮影依頼のメールが Gmail に届く
2. **受注する** — 依頼を受けることを決め、撮影日・会場・ご両家名が確定する
3. **稼働する** — 現場へ向かい、撮影し、帰る。行き帰りの経路とタクシー利用の有無は、この日に確定する
4. **覚えておく** — 使った経路・運賃・タクシー代を、提出まで自分で覚えている、あるいは控えておく
5. **月初にまとめて手入力する** — 委託元のスプレッドシートに、前月分をすべて手で書き写す
   - 交通費（区間と金額）
   - 結婚式場の場所
   - ご両家名
   - タクシーに乗ったか、乗っていないか
6. **領収書を処理する** — タクシーに乗った分は、領収書の画像を Google ドライブに保管し、
   スプレッドシートに貼る。これも手作業

## 4. 現状の課題

**(1) 入力がすべて手作業で、量が多い**

交通費・会場・ご両家名・タクシー有無・領収書。1案件ごとにこれだけの項目を、月初にまとめて手で書き写している。

**(2) 思い出しコストがかかる**

経路とタクシー利用が確定するのは稼働日当日。しかし提出は月初。
**確定した時点と記録する時点が最大1か月離れている**ため、月初の作業は「あの日はどう行ったか」を
思い出すところから始まる。

**(3) 入力したい場所と、入力できる場所がずれている**

経路が確定するのは現場からの帰り道である。だが現状の入力先は PC 前提のスプレッドシートで、
その場では入力できない。結果として、記憶か手控えに頼るしかない。

**(4) 経路を決め打ちにできないので、定型化もできない**

「この会場ならこのルート」と固定できれば定型化できるが、同じ会場でも複数の行き方があり、
どれを使ったかは当日にならないと決まらない。そのため毎回ゼロから書くことになる。

**(5) 領収書の扱いが手数を増やしている**

タクシー分は、領収書をドライブに置き、スプレッドシートに貼る、という別作業が発生する。

## 5. アプリで実現したいこと（To-Be）

### シーン① 依頼が来たとき

Gmail に届いた依頼メールから、案件が **自動でアプリに入っている**。自分では何もしない。
拾えなかった案件や取り違えだけ、後から手で直す。

### シーン② 現場からの帰り道

その日に使った経路が確定した時点で、**移動中のスマートフォンから、その場で記録を終える**。
案件を選び、登録済みのルートから実際に使ったものを選ぶだけでよい。
タクシーを使った日は、金額を入れて領収書をアップロードすれば、ドライブへの保管まで終わっている。

### シーン③ 月初の提出

前月分がすでに揃っているので、内容を確認して **書き込むだけ**。
委託元のスプレッドシートに反映されたら、その月分の作業は完了する。以降そのデータを見ることはない。

## 6. 要求一覧

優先度は次の2段階とする。

- **必須** — これが無いと「4. 現状の課題」が解けない
- **望ましい** — あるとよいが、無くても運用は回る

### 6.1 案件管理

| ID | 要求 | なぜ要るのか | 優先度 |
| --- | --- | --- | --- |
| R-01 | Gmail に届く依頼メールから、撮影案件を自動で取り込みたい | 案件情報の出どころはメールしかない。ここが自動になれば入力の起点が消える | 必須 |
| R-02 | 取り込んだ案件を受注として確定し、一覧で見られるようにしたい | 提出前に「前月分が全部揃っているか」を確かめる土台になる | 必須 |
| R-03 | 案件に、提出に必要な情報（撮影日・会場・ご両家名）が紐づいていてほしい | これらは提出シートの記入項目そのもの。案件側に無いと結局手入力になる | 必須 |
| R-04 | 自動で拾えなかった案件を手で足せる／取り違えを直せるようにしたい | 自動取り込みは必ず取りこぼす。逃げ道が無いと提出漏れになる | 必須 |

### 6.2 ルート管理

| ID | 要求 | なぜ要るのか | 優先度 |
| --- | --- | --- | --- |
| R-05 | よく使う通勤ルートを登録しておきたい（区間・乗り換え・運賃） | 毎回ゼロから区間と運賃を書いている手間（課題4）を無くすため | 必須 |
| R-06 | 会場とルートの紐付けを、アプリ上で管理・変更したい | どの会場にどのルートを使うかは自分で決めたい。自動推測に任せたくない | 必須 |
| R-07 | 1つの会場に複数のルートを紐付けられるようにしたい | 同じ会場でも行き方が複数あり、当日の実績に応じて選ぶ必要があるため | 必須 |
| R-08 | 往復セットで1件として入力するのを基本としつつ、往路・復路を別々に指定もできるようにしたい | 大半は往復同じ経路だが、帰りだけタクシーなど、行きと帰りが違う日もある | 必須 |

### 6.3 交通費入力

| ID | 要求 | なぜ要るのか | 優先度 |
| --- | --- | --- | --- |
| R-09 | 案件を選び、その日に実際に使ったルートを選ぶだけで交通費が確定するようにしたい | 経路が確定するのは当日。選ぶだけで済めば、その場で終えられる | 必須 |
| R-10 | 1日の終わりに、移動中のスマートフォンから短時間で入力を終えられるようにしたい | 入力したい場所と入力できる場所のズレ（課題3）を解消し、思い出しコスト（課題2）を無くす | 必須 |

### 6.4 領収書

| ID | 要求 | なぜ要るのか | 優先度 |
| --- | --- | --- | --- |
| R-11 | タクシーを使った日は、金額と領収書を記録したい | 提出シートにタクシー有無と領収書の記入が要るため | 必須 |
| R-12 | 領収書はタクシー乗車1回につき1件。その1件をアップロードできるようにしたい | 乗車と領収書は常に1対1で対応する | 必須 |
| R-13 | 領収書の実体は、紙を撮影した画像のことも PDF のこともある。どちらの形式でも受け付けたい | 紙の領収書をもらう場合と、配車アプリから PDF を落とす場合の両方があるため | 必須 |
| R-14 | アップロードした領収書が Google ドライブへ自動で保存されるようにしたい | 現状は自分でドライブへ置いている（課題5）。ここを無くす | 必須 |
| R-15 | 保存先の Google ドライブ URL が提出シートに反映されるようにしたい | 現状は自分でシートに貼っている（課題5）。ここを無くす | 必須 |

### 6.5 提出

| ID | 要求 | なぜ要るのか | 優先度 |
| --- | --- | --- | --- |
| R-16 | 月初に、前月分をまとめて委託元の Google スプレッドシートへ書き込めるようにしたい | 月初の手入力（課題1）そのものを無くすのが、このアプリの目的 | 必須 |
| R-17 | 提出前に内容を確認できるようにしたい | 提出先は先方の所有物であり、誤った内容をそのまま書き込むわけにいかない | 必須 |
| R-18 | 提出が済んだ月の実績データは、アプリから消せるようにしたい | 提出後にそのデータを活用する意図が無く、残しておく必要がないため | 望ましい |

### 6.6 非機能・制約

| ID | 制約 | なぜそうなるのか |
| --- | --- | --- |
| N-01 | 主な利用環境はスマートフォン（移動中・屋外）。PC 前提の操作量にしない | 入力する場所が現場への道中と帰り道だから |
| N-02 | Google Workspace（Gmail / Google ドライブ / Google スプレッドシート）が前提環境 | 依頼受信・領収書保管・提出のすべてがこの上で回っている |
| N-03 | 利用者は本人のみ | 自分専用として使う。共有・権限分離の要求は無い |
| N-04 | 提出先スプレッドシートは委託元の所有物。壊さないこと、様式変更に追従できることが要る | 自分の資産ではないため、書き込みで既存の内容を損なってはならない |
| N-05 | **アプリが扱うのは「提出前の前月分」だけ。** 提出後の記録の正本は提出シートと Google ドライブ（領収書）にあり、アプリは正本ではない | アプリの目的は「前月分を入力し終えること」であり、記録の保管庫ではない |
| N-06 | ただし **ルートの登録内容と会場との紐付けは、毎月使い回す設定データとして残り続ける** | ここが消えると「登録済みルートを選ぶだけで済む」（R-05〜R-07）が成立しない |

> **N-05 と N-06 の区別は重要。**
> 消えてよいのは **月次の実績データ**（案件・交通費・領収書）。
> 残り続けるのは **設定データ**（ルート、会場とルートの紐付け）。

## 7. 対象外（今回やらないこと）

| やらないこと | 理由 |
| --- | --- |
| 自家用車の実費（ガソリン・高速・駐車場）の精算 | ヒアリングで対象外と確認。精算する費目は公共交通とタクシーの2つ |
| 宿泊費など交通費以外の立替精算 | 同上 |
| 複数の委託元・複数様式への対応 | 委託元は1社、提出シートも常に1種類と確認 |
| 複数ユーザー／チーム利用 | 自分専用と確認（N-03） |
| 経路検索サービスによる運賃の自動算出 | 登録したルートを選ぶ方式を採ると確認。ただし将来の選択肢としては残す |
| 報酬・請求額の管理 | 今回の対象は交通費の精算のみ |
| 過去分データの蓄積・振り返り・集計・分析 | 提出後のデータは残す必要がないと確認（N-05）。目的は「前月分を入力し終えること」であって履歴の活用ではない |

## 8. 未確定事項

要件定義に入る前に確かめる。

### 実物を見せてもらう必要があるもの

- [ ] **提出先スプレッドシートの実物** — 列構成、月次シートがどう作られるか、
      1行の粒度（案件単位か経路単位か）、タクシー領収書の記入欄がどうなっているか
- [ ] **依頼メールの実物** — 差出人、件名のパターン、本文の書式、
      案件情報（撮影日・会場・ご両家名）がどこにどう書かれているか
- [ ] **現状の領収書 Google ドライブフォルダ** — フォルダ構成と命名規則

### 委託元との取り決めを確かめるもの

- [ ] 提出先スプレッドシートへの編集権限と、API 経由で書き込めるかどうか
- [ ] 「ご両家名」の表記ルール（シート上でどう書くことになっているか）
- [ ] 提出期限（月初の何日までか）と、対象期間（前月1日〜末日でよいか）
- [ ] 提出後に差し戻し・修正依頼が来ることはあるか
      （あるなら、実績データを消した後に直せる必要が出る。R-18 に影響する）

### 運用を確かめるもの

- [ ] 1か月あたりの案件数の目安
- [ ] 依頼を辞退することがあるか。あるとき、取り込んだ案件をどう扱うか
- [ ] 案件のキャンセル・日程変更が起きたときの扱い
- [ ] 提出後の実績データを消すタイミングと方法（提出完了時に自動で消えるのか、自分で消すのか）

## 9. 用語集

| 用語 | 意味 |
| --- | --- |
| 委託元 | 撮影業務を発注してくる企業。現在1社 |
| 案件 | 1件の撮影業務。撮影日・会場・ご両家名で識別される |
| 受注 | 届いた依頼を受けることを決め、案件として確定させること |
| 会場 | 撮影する結婚式場 |
| ご両家名 | 結婚する二人の両家の姓。提出シートの記入項目のひとつ |
| ルート | 自宅と会場の間の行き方。区間・乗り換え・運賃の組み合わせ |
| 往路／復路 | 会場へ向かう行き／会場から帰る行き。別々のルートになることがある |
| 提出シート | 委託元が用意した Google スプレッドシート。交通費の提出先 |
| 実績データ | ある月に実際に発生した案件・交通費・領収書。提出後は残す必要がない（N-05） |
| 設定データ | ルートの登録内容と、会場とルートの紐付け。毎月使い回す（N-06） |
